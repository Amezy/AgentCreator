## 1. 架构概述

### 1.1 系统定位
AI-BOX Box-System 是部署在每台 AI-BOX 物理设备上的本地管理系统，作为云端 Daemon 与本地开发环境之间的桥梁，负责 Agent 团队的配置、运行和监控。

### 1.2 设计原则
- **最小依赖**: 使用嵌入式 SQLite，无需外部数据库
- **安全优先**: 所有敏感数据加密存储，多层认证
- **实时响应**: WebSocket 实时推送状态和事件
- **可观测性**: 完整的日志和监控体系

## 5. 接口设计

### 5.1 REST API 设计原则
- **版本化**: `/api/v1/...`
- **资源导向**: `/users`, `/agents`, `/teams`
- **标准 HTTP 方法**: GET/POST/PUT/DELETE
- **统一响应格式**: `{ success: true, data: {...} }`

### 5.2 核心 API 端点

#### 认证
| 端点 | 方法 | 请求 | 响应 |
|------|------|------|------|
| `/auth/login` | POST | `{username, password}` | `{token, user}` |
| `/auth/refresh` | POST | `Authorization: Bearer` | `{token}` |

#### 用户
| 端点 | 方法 | 说明 |
|------|------|------|
| `/users` | GET | 用户列表 |
| `/users` | POST | 创建用户 |
| `/users/:id` | PUT | 更新用户 |
| `/users/:id` | DELETE | 删除用户 |

#### Agent
| 端点 | 方法 | 说明 |
|------|------|------|
| `/agents` | GET | Agent 列表 |
| `/agents/:id/start` | POST | 启动 Agent |
| `/agents/:id/stop` | POST | 停止 Agent |
| `/agents/:id/logs` | GET | Agent 日志 |

### 5.3 WebSocket 消息协议
```typescript
// 认证握手
Client → Server: { type: 'auth', token: '<JWT>' }
Server → Client: { type: 'auth:success' }

// Agent 状态推送
Server → Client: { 
  type: 'agent:status', 
  agentId: 1, 
  status: 'coding' 
}

// 系统告警
Server → Client: { 
  type: 'system:alert', 
  alertType: 'memory_high', 
  message: '内存使用率 92%' 
}

// 日志订阅
Client → Server: { type: 'subscribe:logs', agentId: 1 }
Server → Client: { type: 'log', agentId: 1, data: '...' }
```

### 6.1 认证流程
```

│  用户   │     │  前端   │     │  后端   │     │  Daemon │
└────┬────┘     └────┬────┘     └────┬────┘     └────┬────┘
     │               │               │               │
     │  输入密码     │               │               │
     │──────────────>│               │               │
     │               │               │               │
     │               │  POST /login  │               │
     │               │──────────────>│               │
     │               │               │               │
     │               │               │  查询管理员   │
     │               │               │──────────────>│
     │               │               │               │
     │               │               │  返回用户信息 │
     │               │               │<──────────────│
     │               │               │               │
     │               │               │  PAM 验证     │
     │               │               │──────────────>│
     │               │               │               │
     │               │               │  验证结果     │
     │               │               │<──────────────│
     │               │               │               │
     │               │               │  生成 JWT     │
     │               │               │               │
     │               │  返回 Token   │               │
     │               │<──────────────│               │
     │               │               │               │
     │  Token        │               │               │
     │<──────────────│               │               │
     │               │               │               │
```

### 6.2 数据加密
- **算法**: AES-256-GCM
- **IV**: 12 字节随机
- **AuthTag**: 128 位
- **密钥来源**: `SWT_MASTER_KEY` 环境变量

### 6.3 权限模型
```
super_admin (工厂初始管理员)
    ├── 全部权限
    └── 可创建 admin

admin (云端下发)
    ├── 用户管理
    ├── 配置管理
    └── 不可删除 super_admin

programmer (普通开发者)
    └── 禁止登录管理系统 (仅 SSH/VS Code)
```

## 8. 架构决策记录 (ADR)

### ADR-001: SQLite 数据库选型
- **决策日期**: 2026-02-28
- **决策**: 使用 SQLite (better-sqlite3) 作为主数据库
- **理由**: 
  - 零运维成本
  - 单文件备份
  - 适合嵌入式部署
- **权衡**: 并发写入受限，但对本场景足够

### ADR-002: PAM 认证
- **决策日期**: 2026-02-28
- **决策**: 使用 PAM 进行用户认证，数据库不存储密码
- **理由**:
  - 与 Linux 系统用户同步
  - 避免双重密码
  - 安全性更高
- **权衡**: 依赖 PAM 可用性

### ADR-003: WebSocket 独立端口
- **决策日期**: 2026-03-01
- **决策**: WebSocket Server 运行在独立端口 3011
- **理由**:
  - 架构简洁
  - 独立扩缩容
  - 避免与 HTTP 请求竞争
- **权衡**: Nginx 配置稍复杂

### ADR-004: JWT Token 24 小时有效期
- **决策日期**: 2026-03-01
- **决策**: JWT Token 有效期 24 小时
- **理由**:
  - 平衡安全性和便利性
  - 本地部署，风险可控
- **权衡**: 需要定期刷新

## 9. 扩展性设计

### 9.1 水平扩展
- **多 Box 设备**: 通过云端 Daemon 统一管理
- **负载均衡**: Nginx 反向代理
- **会话共享**: JWT 无状态认证

### 9.2 垂直扩展
- **资源限制**: Agent CPU/内存可配置
- **熔断机制**: 自动挂起异常 Agent
- **队列管理**: LLM 请求队列和限流

### 9.3 插件扩展
- **Agent Superpowers**: 自定义 Prompt 和规则
- **服务扩展**: 新增服务模块
- **路由扩展**: 新增 API 端点

## 10. 监控与可观测性

### 10.1 监控指标
- **系统指标**: CPU、内存、磁盘
- **应用指标**: API 延迟、错误率
- **业务指标**: Agent 状态、任务完成率

### 10.2 日志体系
- **结构化日志**: JSON 格式
- **日志级别**: trace/debug/info/warn/error/fatal
- **日志输出**: stdout (systemd) + 文件轮转

### 10.3 告警机制
- **资源告警**: 内存 > 85%
- **Agent 告警**: 连续错误熔断
- **网络告警**: DNS 探测失败

## 11. 灾难恢复

### 11.1 备份策略
- **数据库备份**: 每日自动备份
- **配置文件备份**: 版本控制
- **凭证备份**: 加密存储

### 11.2 恢复流程
1. 停止服务
2. 恢复数据库备份
3. 恢复配置文件
4. 重启服务
5. 验证功能

### 11.3 故障转移
- **单点故障**: 当前为单机部署
- **未来规划**: 多 Box 集群，云端 Daemon 协调
