## 5. 性能评估

### 5.1 数据库性能
**现状**:
- SQLite with WAL mode ✅
- 单例连接 ✅
- 事务批量操作 ✅
- 索引覆盖核心查询 ✅

**瓶颈**:
- 并发写入受限 (SQLite 特性)
- 大表查询无分页 (system_events)

**优化建议**:
```sql
-- 添加分页索引
CREATE INDEX idx_events_agent_created ON system_events(agent_id, created_at);

-- 定期清理旧日志
DELETE FROM system_events WHERE created_at < datetime('now', '-30 days');
```

### 5.2 API 性能
**基准测试** (估算):
| 端点 | P95 延迟 | 吞吐量 |
|------|----------|--------|
| GET /users | ~50ms | 100 req/s |
| POST /agents/:id/start | ~200ms | 20 req/s |
| GET /agents/:id/logs | ~100ms | 50 req/s |

**优化建议**:
- 增加响应缓存 (用户信息、配置)
- 异步处理非关键操作 (日志写入)
- 连接池优化 (虽然 SQLite 单例)

### 5.3 WebSocket 性能
**现状**:
- 独立端口 (3011) ✅
- 心跳保活 (30s) ✅
- 认证超时 (10s) ✅

**瓶颈**:
- 无连接数上限
- 消息广播无批量优化

**优化建议**:
```typescript
// 添加连接数限制
const MAX_CONNECTIONS = 100;
if (wsHub.getConnectionCount() >= MAX_CONNECTIONS) {
  ws.close(1013, 'Too many connections');
}
```

### 5.4 内存管理
**现状**:
- 内存监控 (10s 间隔) ✅
- 自动挂起 (>95%) ✅
- Agent 资源限制 ✅

**风险**:
- 阈值可能过于激进 (95%)
- 挂起策略可能影响用户体验

**优化建议**:
- 调整告警阈值 (85% → 80%)
- 调整挂起阈值 (95% → 90%)
- 增加渐进式挂起 (先挂起 idle Agent)
