## 1. 执行摘要

### 产品是什么

AI-BOX Box System（品牌名 **AgentTeam**）是一款运行在物理 AI-BOX 设备（Mac Mini 形态）上的**多用户 AI 开发环境管理系统**。它为企业 AI 开发团队提供一站式的开发者账号创建、Claude Code AI 助手授权、VS Code 远程开发环境部署、AI 模型密钥托管以及 Agent 团队编排能力。

### 解决什么问题

传统方式下，为一位新开发者搭建完整的 AI 辅助开发环境需要 IT 运维人员手动执行以下步骤：创建 Linux 账号、配置 SSH 密钥、安装 VS Code Server、登录 Claude Code OAuth、配置 AI 模型 API Key、关联 Git 仓库等，整个过程通常耗时 **2-4 小时**，且容易出错。

AI-BOX Box System 通过 **5 步配置向导**，让管理员在 **5-10 分钟** 内完成上述全部操作，节省 **95% 以上的人力时间**。

### 核心价值

| 价值维度 | 传统方式 | AgentTeam 方式 | 改进幅度 |
|---------|---------|----------------|---------|
| 环境搭建时间 | 2-4 小时/人 | 5-10 分钟/人 | 提升 95% |
| Claude Code 授权 | 每人每终端单独 OAuth 登录 | 管理员一次授权，全终端共享 | 消除重复操作 |
| VS Code Server 安装 | 手动下载 + 版本匹配调试 | 自动安装 + 版本锁定 | 零人工介入 |
| AI 密钥管理 | 分散存储，各自配置 | 集中配置 + 加密存储 | 降低泄露风险 |
| 开发者上手成本 | 需了解 SSH、环境配置等 | SSH 登录即可使用 | 零学习成本 |

## 2. 产品定位与愿景

### 2.1 目标市场

- **主要市场**: 企业级 AI 开发团队（10-50 人规模）
- **典型客户**: 使用 Claude Code、VS Code Remote 进行 AI 辅助开发的技术团队
- **部署形态**: 本地化部署，运行在企业内网的 AI-BOX 物理设备上

### 2.2 产品愿景

**短期目标（当前版本）**: 成为企业内部 AI 开发环境的"一键式"管理工具，让管理员摆脱繁琐的手动配置工作。

**中期目标（6 个月）**: 打通云端管理台与 Box 设备的联动，实现多 Box 集中管控，支持 Agent 任务实际调度执行。

**长期目标（1 年以上）**: 构建完整的 AI 开发平台，包含开发者自助门户、API Key 用量计费、多租户隔离和插件化 Agent 能力扩展。

### 2.3 产品品牌

- **对外品牌名**: AgentTeam / SuperTeam Wizard
- **技术系统名**: AI-BOX Box System
- **所属产品线**: SuperTeam Wizard（AIBox 软硬件结合产品）

## 3. 用户角色与使用场景

### 3.1 用户角色定义

#### 角色一：超级管理员（Super Admin）

| 属性 | 描述 |
|------|------|
| **身份** | 出厂预设用户（默认用户名 `aiboxadmin`） |
| **职责** | 系统初始化、全局配置、首次部署 |
| **技术水平** | 精通系统运维 |
| **使用频率** | 仅在系统部署和重大维护时使用 |
| **登录方式** | 使用出厂密码或 Linux PAM 密码登录管理 Web UI |
| **权限范围** | 全局读写，可管理所有用户和配置 |

#### 角色二：管理员（Admin）

| 属性 | 描述 |
|------|------|
| **身份** | 由云端守护服务（aibox-daemon）注册的管理员账号 |
| **职责** | 日常管理：创建开发者账号、授权 AI 工具、监控系统状态 |
| **技术水平** | 熟悉 Linux 基本操作、了解 SSH 和 Git |
| **使用频率** | 初始配置时密集使用，之后偶尔管理和维护 |
| **登录方式** | 使用 Linux PAM 密码登录管理 Web UI |
| **权限范围** | 全局读写，与超级管理员权限基本一致 |

#### 角色三：开发者（Programmer）

| 属性 | 描述 |
|------|------|
| **身份** | 由管理员通过管理系统创建的开发者账号 |
| **职责** | 使用 Claude Code 和 VS Code Remote 进行日常开发工作 |
| **技术水平** | 精通编程和开发工具 |
| **使用频率** | 每天高频使用终端和 IDE |
| **登录方式** | 通过 SSH 登录 Box 设备终端，**不登录管理 Web UI** |
| **权限范围** | 仅限使用管理员为其配置好的开发环境 |

#### 角色四：守护服务（Daemon）

| 属性 | 描述 |
|------|------|
| **身份** | Box 上运行的 `aibox-daemon` 守护进程 |
| **职责** | 与云端管理台通信，接收并执行云端下发的指令 |
| **交互方式** | 通过内部 API（本地 IP + Token 认证）调用 Box System |
| **权限范围** | 系统级操作：创建/删除管理员用户、冻结/恢复 Agent |

### 3.2 用户故事

#### 超级管理员的用户故事

- **US-SA01**: 作为超级管理员，我希望用出厂账号密码登录系统，以便进行初始化配置。
  - AC: 使用 `aiboxadmin` / `changeme123` 可以成功登录，进入配置向导。

- **US-SA02**: 作为超级管理员，我希望能管理所有用户的所有配置，以便在管理员不在场时也能处理问题。
  - AC: 超级管理员可以查看和编辑任何用户的模型、团队、部署、仓库配置。

#### 管理员的用户故事

- **US-A01**: 作为管理员，我希望通过 5 步向导快速为新加入的开发者创建完整的开发环境，以便开发者能在 10 分钟内开始工作。
  - AC: 完成向导后，开发者可以通过 SSH 登录 Box，使用 `claude` 命令启动 Claude Code。

- **US-A02**: 作为管理员，我希望一次完成 Claude Code 授权后，开发者的所有终端窗口都能共享这个授权，以便避免每个终端都要重新登录。
  - AC: 管理员在 Web UI 完成 OAuth 授权后，开发者在任意终端执行 `claude` 均无需再次登录。

- **US-A03**: 作为管理员，我希望在账号概览页面以用户为中心管理所有配置，以便快速定位和修改某个开发者的设置。
  - AC: 点击用户卡片展开后，可以看到该用户的模型、团队、部署、仓库、VS Code、Claude 认证、SSH 密钥共 7 个配置区域。

- **US-A04**: 作为管理员，我希望安全地存储所有 AI 模型的 API Key，以便防止密钥泄露。
  - AC: API Key 使用 AES-256-GCM 加密存储，API 响应中不返回原文。

- **US-A05**: 作为管理员，我希望删除开发者时自动清理所有关联数据和系统账号，以便不留下孤立资源。
  - AC: 删除用户后，其 Linux 账号、数据库中所有关联记录（10 个表）均被清理。

- **US-A06**: 作为管理员，我希望能为开发者配置 SSH 公钥，以便开发者可以通过密钥认证登录 Box。
  - AC: 添加的公钥自动部署到用户的 `~/.ssh/authorized_keys`。

#### 开发者的用户故事

- **US-D01**: 作为开发者，我希望 SSH 登录 Box 后就能直接使用 Claude Code，不需要额外配置。
  - AC: `ssh user@box-ip` 登录后，输入 `claude` 即可启动 Claude Code CLI。

- **US-D02**: 作为开发者，我希望使用 VS Code Remote SSH 连接到 Box，获得与本地 IDE 一致的开发体验。
  - AC: VS Code 通过 Remote SSH 连接后，可以正常打开项目、编辑文件、运行终端。

## 4. 用户旅程地图

### 4.1 旅程一：首次配置向导（管理员核心旅程）

这是产品最核心的价值链，将传统 2-4 小时的环境搭建压缩到 5 步向导。

```
管理员登录 ──→ 第 1 步：用户配置 ──→ 第 2 步：模型配置 ──→ 第 3 步：团队配置
                                                                      │
              第 5 步：Git 配置 ←── 第 4 步：部署配置 ←────────────────┘
                     │
                     ▼
              保存所有配置 ──→ 进入账号概览页面
```

**第 1 步：创建开发者账号**

- 管理员输入用户名和密码
  - 用户名规则：以小写字母或下划线开头，仅含小写字母、数字、下划线、连字符，长度 3-32 字符
  - 密码规则：至少 6 个字符
- 点击"下一步"后，系统**立即保存**，自动创建 Linux 系统用户、SSH 目录，并后台启动 VS Code Server 安装
- 如果用户名已存在，系统验证密码后直接跳到下一步
- 耗时：约 2-3 秒

**第 2 步：配置 AI 模型**

- 管理员选择 AI 模型提供商（支持 Anthropic、Google；OpenAI 暂不可用）
- Anthropic 模型（Opus 4.6、Sonnet 4.6）需要通过 OAuth 认证流程激活
  - 点击"获取认证串"，系统生成 OAuth 链接
  - 管理员在新浏览器窗口打开链接，完成 Claude 登录授权
  - 将获得的授权码粘贴回系统，点击"激活"
- Google 模型直接输入 API Key 完成配置
- 选择提供商后自动包含该提供商的所有可用模型

**第 3 步：配置 Agent 团队**

- 基于 Superpowers 工作流范式组建 AI 开发团队
- 系统预设 5 个角色：架构师、前端开发、后端开发、代码审查、DevOps
- 每个角色固定 1 个 Agent，为每个角色分配已验证的 AI 模型
- 输入团队名称（如"默认团队"、"前端加强版"）
- 每个角色显示其 Superpowers 技能标签（如 brainstorming、test-driven-development 等）

**第 4 步：部署配置**

- 选择部署方式：本地部署或云端部署
- 本地部署无需额外配置，可直接进入下一步
- 云端部署需填写服务器 IP、端口、用户名、密码

**第 5 步：Git 仓库配置**（可跳过）

- 可勾选"暂不配置 Git 仓库"跳过此步骤
- 选择代码平台：GitHub、GitLab（私有云）、Gitee 或自定义平台
- 输入私人访问令牌并验证仓库连接
- 验证成功后显示分支和标签列表

**最终提交**：点击"完成"按钮，系统依次保存模型、团队、部署、仓库共 4 项配置（第 1 步已在"下一步"时保存），然后自动跳转到账号概览页面。

### 4.2 旅程二：Claude Code OAuth 授权流程

这是系统中最关键也最复杂的用户旅程，涉及管理 Web UI、Claude 网站、开发者终端三方交互。

```
步骤 1: 管理员在概览页/向导中点击"开始认证"或"获取认证串"
    │
    ▼
步骤 2: 系统后台生成 PKCE 安全参数（code_verifier + code_challenge + state）
    │     返回 OAuth 认证链接
    ▼
步骤 3: 管理员在新浏览器标签页打开认证链接
    │     进入 claude.ai 登录/授权页面
    │     完成授权后获得授权码
    ▼
步骤 4: 管理员将授权码粘贴回管理系统
    │     （支持三种格式：裸授权码、code#state、完整回调 URL）
    ▼
步骤 5: 系统用授权码换取访问令牌（Token）
    │     成功后写入目标用户的 ~/.claude/ 目录
    ▼
步骤 6: 该用户所有 SSH 终端自动共享 Claude Code 授权
         开发者无需任何额外操作
```

**关键注意事项**：
- OAuth 系统会话有效期为 5 分钟（可配置），建议 5 分钟内完成操作
- 授权码只能使用一次
- Token 交换使用 PKCE + state 防 CSRF 攻击机制
- 凭据文件权限设为 600（仅属主可读）

### 4.3 旅程三：VS Code Server 自动安装

```
用户创建/确认 ──→ 后台自动开始安装 VS Code Server
                       │
                       ├── 安装中（前端每 5 秒轮询状态）
                       │   显示：旋转图标 + "正在安装，请稍候..."
                       │
                       ├── 安装成功
                       │   显示：版本 Commit ID + 已安装扩展列表
                       │
                       └── 安装失败
                           显示：错误信息 + [重新安装] 按钮
```

- 预装版本：VS Code 1.109.5（commit 072586267e68ece9a47aa43f8c108e0dcbf44622）
- 安装方式：从本地资源包部署，无需联网下载
- 安装超时：2 分钟
- 包含 Claude Code 插件的自动安装

### 4.4 旅程四：日常管理（账号概览）

管理员登录后进入"账号概览"页面，以用户卡片列表的形式展示所有用户。

```
账号概览页面
    │
    ├── 超级管理员卡片（aiboxadmin）
    │     └── 无法编辑/删除
    │
    ├── 管理员卡片（由守护服务创建）
    │     └── 可查看，部分操作
    │
    └── 开发者卡片（由管理员创建） ←── 核心管理对象
          │
          └── 点击展开后显示 7 个配置区域：
              ├── 1. 模型配置：已配置的 AI 模型列表和验证状态
              ├── 2. 团队配置：Agent 团队组成和模型分配
              ├── 3. 部署配置：本地/云端部署目标
              ├── 4. Git 仓库：关联的代码仓库
              ├── 5. VS Code Server：安装状态和版本
              ├── 6. Claude 认证：OAuth 状态和过期时间
              └── 7. SSH 密钥：已部署的公钥列表
```

每个配置区域均支持新建、编辑、删除操作（通过弹窗对话框）。

### 4.5 旅程五：开发者终端体验

开发者全程不接触管理 Web UI，所有配置由管理员完成。

```
开发者收到账号信息（用户名 + 密码 / SSH 密钥）
    │
    ├── 路径 A：命令行终端
    │     ssh user@box-ip
    │     → 输入 claude 启动 Claude Code CLI
    │     → 开始 AI 辅助编程
    │
    └── 路径 B：VS Code Remote
          VS Code 中安装 Remote SSH 扩展
          → 连接到 box-ip
          → 打开远程项目
          → 使用 Claude Code 插件
```

## 7. 数据流与业务规则

### 7.1 用户创建数据流

```
管理员输入用户名密码
    │
    ▼
数据库 INSERT users 记录（role = programmer）
    │
    ▼
Linux useradd 创建系统用户
    │  + 设置密码
    │  + 创建 HOME 目录和 SSH 目录
    │
    ├── 失败 → 回滚数据库 DELETE
    │
    └── 成功 → 异步安装 VS Code Server
                    │
                    └── Fire-and-forget（不阻塞响应）
```

### 7.2 Claude OAuth 认证数据流

```
管理员点击"开始认证"
    │
    ▼
后端生成 PKCE 安全参数
    │
    ▼
返回 OAuth 认证链接
    │
    ▼
管理员在浏览器完成 Claude 登录并获取授权码
    │
    ▼
后端用授权码向 Anthropic 换取访问令牌
    │
    ├── 失败 → 记录错误，返回失败信息
    │
    └── 成功 → 写入目标用户 HOME 目录凭据文件
                    │
                    ▼
              该用户所有终端自动共享 Claude Code 授权
```

### 7.3 用户级联删除规则

删除一个用户时，系统按以下顺序清理所有关联数据：

1. 删除 Agent Superpowers 配置
2. 保留系统事件记录（解除关联）
3. 删除 Agent 实例
4. 删除团队配置
5. 删除模型凭据
6. 删除部署配置
7. 删除 Git 仓库配置
8. 删除 SSH 密钥
9. 删除用户数据库记录
10. 终止 Linux 用户进程
11. 删除 Linux 系统用户

以上数据库操作在一个事务中执行，保证原子性。

### 7.4 关键业务规则

| 规则 | 描述 |
|------|------|
| 每用户限一个团队 | 每个开发者最多创建一个 Agent 团队 |
| 模型凭据三元唯一 | 同一用户 + 同一提供商 + 同一模型名 唯一 |
| 用户名 Unix 规范 | 小写字母或下划线开头，仅含小写字母、数字、下划线、连字符，3-32 字符 |
| 密码最低复杂度 | 至少 6 个字符 |
| SSH 密钥指纹唯一 | 不允许同一把密钥重复添加 |
| VS Code 安装并发锁 | 同一用户同时只能有一个安装进程 |
| OAuth 会话过期 | 认证会话 5 分钟后自动过期 |
| 模型删除时团队解绑 | 删除模型凭据时，引用该模型的团队配置自动置空 |
| 不可删除自身 | 管理员不能删除自己的账号 |
| 敏感字段不返回 | API Key、密码等加密字段从不在 API 响应中返回 |

| SSH 连接测试 | 云端部署配置无法验证目标服务器可达性，误导用户以为配置成功 | 中 |
| Git 仓库连接测试（已保存仓库） | 无法预检仓库访问权限，误导用户以为配置成功 | 中 |
| Agent 实际执行 | 核心功能未落地，团队启动后 Agent 不执行任务，仅创建数据库记录 | **高** |
| 磁盘使用率 | 始终显示 50%，无法预警磁盘满，可能导致安装失败 | 中 |

> 注意：向导中的 Git 仓库连接验证（使用 git ls-remote 实际验证）是**真实实现**的，仅已保存仓库的连接测试为 Mock。

### 9.2 用户体验痛点

| 问题 | 严重程度 | 描述 | 建议 |
|------|---------|------|------|
| OAuth 认证链接无过期倒计时 | 高 | 5 分钟过期但 UI 无任何时间提示 | 添加倒计时组件，过期前 2 分钟弹出提醒 |
| VS Code 版本匹配要求无提示 | 高 | 预装版本 1.109.5，客户端不匹配时无法连接但无说明 | 在 VS Code 状态区显示兼容版本号和下载链接 |
| 向导完成时一次保存多项配置 | 中 | 任何一项失败只有一个笼统提示 | 添加分步保存进度条，分项显示成功/失败 |
| OAuth 授权码格式不明确 | 中 | 用户不确定该粘贴裸码、code#state 还是完整 URL | 添加格式说明和示例 |
| 需切换浏览器窗口完成 OAuth | 中 | 在管理界面和 Claude 网站之间来回切换 | 未来考虑嵌入式 OAuth 或自动回调 |
| 模型选择按钮尺寸偏小 | 低 | 团队配置中模型选择 pill 不易识别为可点击 | 增大尺寸，添加 hover 效果 |
| 表单数据无自动保存 | 中 | 向导刷新页面后已填内容丢失 | 使用 localStorage 持久化向导进度 |

### 9.3 技术债务对产品的影响

| 技术债务 | 产品影响 | 严重程度 |
|---------|---------|---------|
| OAuth 会话存储在内存 | 服务重启丢失所有进行中的认证流程 | 中 |
| VS Code 安装进度存储在内存 | 服务重启丢失安装状态 | 低 |
| 无 API 速率限制 | 认证接口可被暴力攻击 | 高 |
| JWT 无刷新令牌机制 | 24 小时后强制重新登录 | 低 |
| 无软删除 | 误删用户数据不可恢复 | 中 |
| 两套 WebSocket 实现共存 | 实时推送功能（Agent 状态变更等）未激活 | 中 |
| Root Daemon 后台任务未启动 | 资源监控定时检查、Agent 心跳检查、网络连通性检查均未运行 | 中 |
| 用户名双层校验不一致 | API 层允许 3-50 字符但系统层限制 3-32 字符，中间区间会导致创建失败 | 低 |

### 9.4 安全风险

| 风险 | 影响 | 当前缓解 | 建议 |
|------|------|---------|------|
| JWT Secret 硬编码默认值 | 开发环境默认密钥可被猜测 | 生产环境通过环境变量覆盖 | 强制生产环境必须配置自定义密钥 |
| 出厂密码公开 | changeme123 在代码和文档中可见 | 首次登录后应修改 | 强制首次登录修改密码 |
| 无登录失败锁定 | 暴力破解风险 | 无 | 实现登录失败次数限制和临时锁定 |
| system_events 无清理策略 | 日志持续增长导致数据库膨胀 | 无 | 添加自动清理（保留 90 天） |

## 11. 业务指标与成功标准

### 11.1 关键指标（KPI）

| 指标类别 | 具体指标 | 目标值 | 衡量方式 |
|---------|---------|--------|---------|
| **效率指标** | 用户从创建到可用的平均耗时 | < 5 分钟 | 创建时间戳 -> 首次 SSH 登录时间 |
| **效率指标** | 配置向导完成率 | > 85% | 各步骤漏斗转化统计 |
| **效率指标** | 管理员操作时长节省 | > 90% | 对比传统手动配置时间 |
| **可靠性指标** | VS Code 安装一次成功率 | > 95% | system_events 中 vscode_install 事件统计 |
| **可靠性指标** | Claude OAuth 认证一次成功率 | > 80% | 认证会话成功/失败比例 |
| **使用指标** | 日活跃管理员数（DAU） | 根据团队规模 | 登录日志统计 |
| **安全指标** | 认证失败次数/天 | < 10 次/天 | 登录失败日志统计 |

### 11.2 成功标准定义

- 管理员可以在 10 分钟内通过 5 步向导完成一个开发者的完整环境配置
- 开发者 SSH 登录后可以直接使用 Claude Code CLI，无需任何额外配置
- 开发者使用 VS Code Remote SSH 连接后可以正常开发
- 所有 AI 模型的 API Key 均加密存储，API 响应不泄露原文
- 删除用户后所有关联数据和系统账号被完整清理
- 系统在无人值守情况下稳定运行，服务崩溃后由 systemd 自动恢复
- 向导流程的五个步骤的完成率漏斗中，每步流失率 < 15%

## 附录 B：简化版数据模型

```
用户（User）
  ├── 模型凭据（Model Credentials）     多个提供商的 API Key / OAuth
  ├── 团队配置（Team Config）            1 个团队，5 个角色
  │   └── Agent 实例（Agent Instances）  每角色 1 个 Agent
  │       └── Superpowers 配置          自定义提示词和规则
  ├── 部署配置（Deploy Config）          本地 / 云端
  ├── Git 仓库（Git Repos）             多个仓库
  ├── SSH 密钥（SSH Keys）              多把公钥
  ├── Claude 认证（Claude Auth）        OAuth Token（磁盘文件，非数据库）
  └── VS Code Server                   安装状态（内存追踪，非数据库）
```

**关键数据关系**：
- 删除用户时，所有上述关联数据全部级联清理
- 删除模型凭据时，引用该模型的团队角色自动解绑
- Agent 实例删除时，系统事件记录保留（仅解除关联）
