## 1. 产品定位与核心价值

### 1.1 产品定位

AI-BOX Box System 是一个**多用户 AI 开发环境管理系统**，面向企业内部 AI 编程团队。管理员通过 Web 控制台完成开发者账号创建、Claude Code 授权、VS Code 服务器部署、模型配置、Agent 团队编排等操作，开发者无需任何配置即可通过 SSH / VS Code Remote 开始 AI 辅助编程。

**核心价值**: 一次管理，多人使用；零配置上手，开箱即用。

### 1.2 核心商业价值

| 痛点 | 传统方式 | AI-BOX 方式 | 价值量化 |
|------|---------|-------------|---------|
| 开发者环境搭建 | 运维手动配 SSH/IDE，2-4 小时/人 | 5 步向导自动化，< 5 分钟/人 | **节省 95% 人力时间** |
| Claude Code 授权 | 每人每终端单独登录 OAuth | 管理员一次授权，全终端共享 | **减少 N×M 次重复认证** |
| VS Code Server 安装 | 手动下载 + 版本匹配 | 自动安装 + 版本锁定 | **消除版本不匹配故障** |
| 多人模型密钥管理 | 每人自行配置 API Key | 集中配置 + 加密存储 | **降低密钥泄露风险** |
| Agent 团队管控 | 无统一管理入口 | 角色编排 + 集中调度 | **可观测、可审计** |

### 3.4 认证流程

1. 输入用户名密码 → PAM 认证 (Linux 系统)

4. 支持 Token 刷新 (`POST /api/v1/auth/refresh`)

## 4. 功能模块详述

### 4.1 用户管理

**功能描述**: 管理员创建/编辑/删除开发者账号，系统自动同步 Linux 系统用户。

| 操作 | 系统行为 |
|------|----------|
| 创建用户 | `useradd` 创建 Linux 用户 → 写入 SQLite → 异步安装 VS Code Server |
| 确保用户存在 | 存在则验证密码并补装 VS Code；不存在则走创建流程 |
| 修改密码 | `chpasswd` 更新系统密码 |
| 启用/禁用 | `usermod --unlock/--lock` + 恢复/设置 nologin shell |
| 删除用户 | `pkill -9` 终止进程 → `userdel -r` 删除用户 → 级联清理 10 个关联表 |

**用户名规则**: `/^[a-z_][a-z0-9_-]{2,31}$/`（小写字母/下划线开头，3-32 字符）
**密码规则**: 最少 6 字符

**级联删除顺序**（事务操作）:
1. 终止 Linux 进程: `killall -u username`
2. 删除 Linux 用户: `userdel -r username`
3. 数据库事务: agent_superpowers → system_events(SET NULL) → agent_instances → team_configs → model_credentials → deployment_configs → git_repositories → user_ssh_keys → users

**API 端点**:
- `GET /api/v1/users` — 列表（合并 Daemon DB + 本地 DB）
- `POST /api/v1/users` — 创建
- `POST /api/v1/users/ensure` — 确保存在
- `GET/PUT/DELETE /api/v1/users/:id` — 详情/更新/删除

### 4.2 Claude Code OAuth PKCE 认证

**功能描述**: 管理员为开发者完成 Claude Code CLI 的一键授权，开发者所有终端自动继承认证。

**认证流程（三方交互）**:

```
┌─────────┐     ┌──────────┐     ┌──────────────┐
│  Admin   │     │ Box API  │     │  Anthropic   │
│(浏览器)  │     │ (后端)   │     │  OAuth 服务  │
└────┬─────┘     └────┬─────┘     └──────┬───────┘
     │                │                   │
     │ 1. 点击激活     │                   │
     ├───────────────>│                   │
     │                │ 2. 生成 PKCE:      │
     │                │    code_verifier   │
     │                │    code_challenge  │
     │                │    state           │
     │ 3. 返回 URL    │                   │
     │<───────────────┤                   │
     │                │                   │
     │ 4. 打开 URL 完成 OAuth 登录         │
     ├────────────────────────────────────>│
     │                │                   │
     │ 5. 获得 authorization_code          │
     │<────────────────────────────────────┤
     │                │                   │
     │ 6. 提交 code   │                   │
     ├───────────────>│                   │
     │                │ 7. JSON POST 交换: │
     │                │    Content-Type:   │
     │                │    application/json│
     │                │    含 state 字段    │
     │                ├──────────────────>│
     │                │                   │
     │                │ 8. 返回 Token      │
     │                │<──────────────────┤
     │                │                   │
     │                │ 9. 写入文件:       │
     │                │  ~/.claude/.credentials.json (mode 600)
     │                │  ~/.claude.json (mode 644)
     │                │                   │
     │ 10. 成功响应   │                   │
     │<───────────────┤                   │
```

**关键技术细节**:
- Token 交换**必须**用 `Content-Type: application/json`（非标准 OAuth 的 form-urlencoded）
- JSON body **必须**包含 `state` 字段（逆向 Claude Code CLI 2.1.63 确认）
- Client ID: `9d1c250a-e61b-44d9-88ed-5944d1962f5e`
- Authorize URL: `https://claude.ai/oauth/authorize`
- Token URL: `https://platform.claude.com/v1/oauth/token`
- 会话超时: 5 分钟（300s），60 秒间隔自动清理过期会话
- 会话存储: 内存 Map（服务重启会丢失进行中会话）

**写入的凭据文件**:
```json
// ~/.claude/.credentials.json (mode 600)
{
  "claudeAiOauth": {
    "accessToken": "sk-ant-oat01-...",
    "refreshToken": "sk-ant-ort01-...",
    "expiresAt": 1772964157124,
    "scopes": ["org:create_api_key", "user:profile", "user:inference"]
  }
}
```

**多终端共享原理**: 同一 Linux 用户的所有终端共享 HOME 目录，Claude CLI 启动时自动读取 `~/.claude/.credentials.json`。

**API 端点**:
- `POST /api/v1/users/:id/claude-auth/login/start` — 启动 OAuth
- `POST /api/v1/users/:id/claude-auth/login/submit-code` — 提交授权码
- `GET /api/v1/users/:id/claude-auth/login/status` — 查询会话状态
- `POST /api/v1/users/:id/claude-auth/login/cancel` — 取消会话
- `GET /api/v1/users/:id/claude-auth/status` — 检查认证状态
- `POST /api/v1/users/:id/claude-auth/logout` — 注销认证

### 4.3 VS Code Server 管理

**功能描述**: 为每个开发者自动安装 VS Code Remote SSH Server 和 Claude Code 插件。

**预装版本**: VS Code 1.109.5, commit `072586267e68ece9a47aa43f8c108e0dcbf44622`

> **重要**: 客户端 VS Code 版本必须匹配此 commit ID 才能使用 Remote SSH。

**安装机制**:
- 创建用户时自动触发异步安装（fire-and-forget）
- 安装脚本: `assets/vscode-server/vscode-cc-plugin-install.sh`
- 并发锁: 同一用户不可重复安装（`installLocks` Set 互斥）
- 超时: 120 秒

**状态检测**:
- 检查 `~/.vscode-server/bin/<commitId>/bin/code-server` 是否存在
- 列出已安装的扩展
- 返回: `{ installed, serverPath, commitId, extensions }`

**前端轮询**: 重装后每 5 秒轮询状态，最长 180 秒超时。

**API 端点**:
- `GET /api/v1/users/:id/vscode-server/status` — 安装状态
- `GET /api/v1/users/:id/vscode-server/install-progress` — 安装进度
- `POST /api/v1/users/:id/vscode-server/reinstall` — 强制重装

### 4.4 模型凭据管理

**功能描述**: 管理 AI 模型的 API Key / OAuth 凭据，支持 Anthropic、Google、OpenAI 三家供应商。

**支持的模型**:

| 供应商 | 模型 | 认证方式 | 状态 |
|--------|------|---------|------|
| Anthropic | Claude Opus 4.6, Sonnet 4.6 | OAuth PKCE | ✅ 可用 |
| Google | Gemini 3 Flash, Gemini 3.1 Pro | API Key | ✅ 可用 |
| OpenAI | GPT-5.3 Codex | API Key | 禁用 |

**安全措施**:
- API Key 使用 AES-256-GCM 加密后存储
- 加密格式: `base64(iv):base64(encrypted):base64(authTag)`
- 主密钥: `SWT_MASTER_KEY` 环境变量 (64 hex chars)
- API 响应永远不返回加密字段原文

**数据唯一约束**: `(user_id, provider, model_name)` — 同用户同供应商同模型只存一条，支持 upsert。

**API 端点**:
- `GET /api/v1/models` — 列表
- `POST /api/v1/models` — 添加/更新（upsert）
- `PUT /api/v1/models/:id` — 更新
- `DELETE /api/v1/models/:id` — 删除
- `POST /api/v1/models/:id/verify` — 验证 ⚠️ **当前为 Mock 实现**

### 4.5 Agent 团队配置

**功能描述**: 为开发者配置 5 角色的 AI Agent 团队，每个角色分配不同的 AI 模型。

**固定角色体系**:

| 角色 | 人数 | 默认模型建议 | Superpowers 技能 |
|------|:---:|-------------|-----------------|
| Architect | 固定 1 | Claude Opus 4.6 | brainstorming, writing-plans, executing-plans |
| Frontend | 固定 1 | Claude Sonnet 4.6 | test-driven-dev, subagent-driven-dev |
| Backend | 固定 1 | Claude Sonnet 4.6 | test-driven-dev, subagent-driven-dev |
| Reviewer | 固定 1 | Gemini 3 Flash | requesting/receiving-code-review, verification |
| DevOps | 固定 1 | Claude Sonnet 4.6 | git-worktrees, dev-branch, parallel-agents |

> **注意**: 代码中所有角色人数固定为 1，不可调整。数据库表虽有 `*_count` 字段支持 1-10，但路由层硬编码为 1。

**约束**:
- 每用户限 1 个团队配置
- 启动团队: 为每个角色创建 `agent_instances` 记录（状态: idle）
- 启动后异步生成 `~/.claude/CLAUDE.md` 配置文件

**Agent 状态流转**:
```
idle → coding → blocked → error → suspended
         ↑                    ↓
         └──── resume ←──────┘
```

**断路器**: 连续 3 次错误自动挂起 + 广播事件通知

**API 端点**:
- `GET/POST /api/v1/teams` — 列表/创建
- `PUT/DELETE /api/v1/teams/:id` — 更新/删除
- `POST /api/v1/teams/:id/launch` — 启动团队
- `POST /api/v1/teams/:id/stop` — 停止团队
- Agent 管理: `GET/POST /api/v1/agents/:id/resume|stop|logs`
- Superpowers: `PUT /api/v1/agents/:id/superpowers`

### 4.8 SSH 密钥管理

**功能描述**: 管理系统 SSH 密钥对和用户 SSH 公钥。

**系统密钥**:
- 生成 ed25519 密钥对: `~/.ssh/swt_ed25519`
- 自动添加 `github.com` 到 known_hosts
- GitHub CLI 集成: 列出/创建仓库

**用户公钥**:
- 解析 OpenSSH 格式公钥 (type, fingerprint SHA256, comment)
- 部署到 `~/.ssh/authorized_keys`（sudo 操作）
- 去重: 基于 fingerprint 唯一约束

**API 端点**:
- `POST /api/v1/ssh/generate` — 生成密钥对
- `GET /api/v1/ssh/public-key` — 获取公钥
- `POST /api/v1/ssh/test-github` — 测试 GitHub SSH
- `POST/GET/DELETE /api/v1/users/:id/ssh-keys` — 用户公钥 CRUD

### 4.9 系统监控

**功能描述**: 实时监控系统资源和 Agent 运行状态。

**资源监控** (每 10 秒采集):
- CPU 使用率（基于 `/proc/stat`）
- 内存使用率（告警: 85% 警告, 95% 严重）
- 磁盘使用率 ⚠️ **当前硬编码为 50%（Mock 实现）**

**自动保护**:
- 内存 > 95%: 自动挂起非核心 Agent（保留 Architect）
- 网络断开: 广播告警
- Agent 心跳超时 (> 60s): 标记为 error

**事件日志**:
- 事件类型: agent_start/stop/error/blocked/circuit_break/resource_alert/network_freeze/rate_limit/deploy_success/deploy_fail/user_action/vscode_install/claude_md_generate/deploy_yaml_generate
- 4 级严重度: info/warn/error/critical
- 支持分页、类型/严重度过滤
- metadata: JSON 扩展字段 (stdout/stderr 截断至 500 字符)

**API 端点**:
- `GET /api/v1/system/health` — 健康检查 (无需认证)
- `GET /api/v1/system/resources` — 资源使用
- `GET /api/v1/system/events` — 事件日志

### 4.11 WebSocket 实时通信

**功能描述**: 独立端口的 WebSocket 服务，提供 Agent 日志和系统事件的实时推送。

**协议**:
- 连接后 10 秒内发送 JWT 认证
- 30 秒心跳 ping/pong
- 订阅模型: 按 Agent ID 订阅日志流

**消息类型**:
```
客户端 → 服务端:
  { type: "auth", token: "..." }
  { type: "subscribe:logs", agent_ids: [...] }
  { type: "unsubscribe:logs", agent_ids: [...] }

服务端 → 客户端:
  auth:success, subscribe:ack, error
  agent:status, system:alert (业务事件)
```

## 5. 前端用户界面

### 5.1 向导式配置流程 (Wizard)

管理员通过 5 步向导为开发者完成完整配置:

```
Step 1: 用户设置     → 输入用户名 + 密码
Step 2: 模型配置     → 选择供应商、完成 OAuth / API Key 认证
Step 3: 团队配置     → 命名团队、为 5 角色分配已验证模型
Step 4: 部署配置     → 选择本地/云端部署
Step 5: Git 仓库     → 可选，配置仓库 + Token + 验证连接
```

**向导完成时**: 批量创建用户 + 保存模型 + 创建团队 + 保存部署 + 保存仓库 → 跳转概览页

**完成时数据提交顺序**:
1. `ensureUser(username, password)` → userId
2. `for each model: createModel(...)` → 收集 modelIdMap
3. `saveTeamConfig(...)` → teamId
4. `saveDeployConfig(...)` → deployId
5. `if (repoUrl): saveRepoConfig(...)` → repoId

### 6.2 关键约束

| 约束 | 实现方式 | 业务原因 |
|------|---------|---------|
| 每用户最多 1 个团队 | 代码检查 (409) | 简化管理 |
| 模型凭据三元唯一 | UNIQUE(user_id, provider, model_name) | 同模型只需一个密钥 |
| 用户名 Unix 规范 | 正则 `/^[a-z_][a-z0-9_-]{2,31}$/` | 与 Linux 用户名兼容 |
| 密码最少 6 字符 | 前后端双重验证 | 基本安全要求 |
| SSH 密钥指纹唯一 | DB 唯一约束 | 防止重复密钥 |

## 7. 安全机制

### 7.1 已实现

| 措施 | 详情 |
|------|------|
| AES-256-GCM | 所有敏感数据加密存储 |
| timing-safe 比较 | Daemon Token 验证防时序攻击 |
| execFile | 替代 exec 防命令注入 |
| 用户名校验 | 正则白名单 |
| JWT 24h 过期 | 防 Token 长期泄露 |
| localhost 限制 | Daemon API 仅本机可访问 |
| SSH 指纹 SHA256 | 密钥去重和验证 |
| PAM 密码代理 | 密码从不存入应用 DB |
| OAuth PKCE + state | 防 CSRF 攻击 |
| 文件权限 600 | Claude 凭据文件仅属主可读 |
| API 响应过滤 | 加密字段从不在 API 返回 |

### 7.2 已知风险

| 风险 | 严重度 | 状态 |
|------|--------|------|
| 出厂密码 `changeme123` 硬编码 | 高 | 待修复 |
| JWT Secret 默认值 `dev-jwt-secret-change-in-production` | 高 | 待修复 |
| API 端点无速率限制 | 中 | 仅 LLM Gateway 有 |
| DB 文件权限未设置 | 中 | 待修复 |
| Token 可能泄露到日志 | 中 | 待过滤 `sk-ant-` 前缀 |
| OAuth Session 内存存储 | 中 | 服务重启丢失进行中会话 |
| VS Code 进度内存存储 | 中 | 服务重启丢失安装进度 |
| JWT 无 Refresh Token 机制 | 低 | 24h 后需重新登录（有 /auth/refresh 续签） |
| 级联删除无软删除 | 低 | 误删数据不可恢复 |
| CORS 宽松策略 | 低 | 仅开发环境 |

## 附录 C: 错误处理策略

| HTTP 状态码 | 含义 | 前端处理 |
|------------|------|---------|
| 400 | 参数校验失败 | Snackbar 显示具体字段错误 |
| 401 | Token 过期/无效 | 跳转登录页 |
| 403 | 权限不足 | Snackbar 提示 "无权执行此操作" |
| 404 | 资源不存在 | Snackbar 提示 |
| 409 | 资源冲突（重复） | Snackbar 提示冲突原因 |
| 500 | 服务器内部错误 | Snackbar 提示 "系统错误，请重试" |
