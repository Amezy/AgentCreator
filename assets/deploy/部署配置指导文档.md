1. ## 脚本使用说明

1. ### 脚本作用

```JSON
generate-deploy-yaml.sh 是一个部署环境配置生成器，用于生成 deploy.yaml 文件，存储服务器连接信息（IP、端口、用户名、密码等），供 Claude Code 执行部署任务时读取使用。
```

#### 工作原理

```Plain
generate-deploy-yaml.sh  →  生成 ~/.claude/deploy.yaml（环境配置）
                                       ↑
CLAUDE.md 中的部署指引  →  告诉 Claude 部署时读取此文件
                                       ↓
用户说"部署到 dev"      →  Claude 读取 yaml → ssh 连接服务器 → 执行部署
```

> `deploy.yaml` 不是 Claude Code 原生自动加载的文件，需要配合 `CLAUDE.md` 中的部署指引使用。
>
> 可通过 `generate-claude-md.sh -d` 自动生成对应的 CLAUDE.md 部署指引段落。

1. ## 命令行参数

```Plain
./generate-deploy-yaml.sh [OPTIONS]
```

| 参数            | 缩写 | 说明                                                         | 默认值                  |
| --------------- | ---- | ------------------------------------------------------------ | ----------------------- |
| `--env SPEC`    | `-e` | 环境配置，格式：`name:host:port:user:password`               | 无（进入交互模式）      |
| `--git SPEC`    | `-g` | Git 仓库配置，格式：`repo_url|branch|auth_method|username|token_or_key` | 无（可选）              |
| `--output FILE` | `-o` | 输出文件路径                                                 | `~/.claude/deploy.yaml` |
| `--help`        | `-h` | 显示帮助信息                                                 | -                       |

1. ### 环境配置格式

```Plain
-e name:host:port:user:password
```

| 字段       | 说明                                       | 是否必填      |
| ---------- | ------------------------------------------ | ------------- |
| `name`     | 环境名称（dev/test/staging/prod 或自定义） | 必填          |
| `host`     | 服务器 IP                                  | 必填          |
| `port`     | SSH 端口                                   | 可选，默认 22 |
| `user`     | SSH 用户名                                 | 必填          |
| `password` | SSH 密码                                   | 可选          |

### Git 仓库配置格式

支持 **两种格式**，使用 `|` 作为分隔符（因为 Git URL 中包含冒号 `:`）。

#### 格式一：Token 认证（推荐）

```Plain
-g "repo_url|branch|token"
```

适用于 GitHub PAT（`github_pat_*`、`ghp_*`）、GitLab PAT（`glpat-*`）等 Token 认证方式。**无需填写用户名**，脚本会自动检测 Token 类型并生成带认证的 clone URL。

| 字段       | 说明                                           | 是否必填          |
| ---------- | ---------------------------------------------- | ----------------- |
| `repo_url` | Git 仓库 HTTPS 地址                            | 必填              |
| `branch`   | 分支名称                                       | 可选，默认 `main` |
| `token`    | Access Token（如 `github_pat_xxx`、`ghp_xxx`） | 必填              |

#### 格式二：完整格式（HTTPS / SSH）

```Plain
-g "repo_url|branch|auth_method|username|token_or_key"
```

| 字段           | 说明                                | 是否必填                       |
| -------------- | ----------------------------------- | ------------------------------ |
| `repo_url`     | Git 仓库地址                        | 必填                           |
| `branch`       | 分支名称                            | 可选，默认 `main`              |
| `auth_method`  | 认证方式：`token` / `https` / `ssh` | 可选，默认 `token`             |
| `username`     | HTTPS 用户名                        | HTTPS 时填写，token 方式可留空 |
| `token_or_key` | HTTPS Access Token 或 SSH 私钥路径  | 按认证方式填写                 |

### 支持的 Token 类型

脚本会自动识别以下 Token 前缀并标注类型：

| Token 前缀    | 类型             | 说明                              |
| ------------- | ---------------- | --------------------------------- |
| `github_pat_` | Fine-grained PAT | GitHub 细粒度个人访问令牌（推荐） |
| `ghp_`        | Classic PAT      | GitHub 经典个人访问令牌           |
| `gho_`        | OAuth            | GitHub OAuth 访问令牌             |
| `ghu_`        | User-to-server   | GitHub App 用户令牌               |
| `ghs_`        | Server-to-server | GitHub App 安装令牌               |
| `glpat-`      | GitLab PAT       | GitLab 个人访问令牌               |

1. ### 预定义环境名称

| name      | 自动映射的中文名 | 自动设置安全策略        |
| --------- | ---------------- | ----------------------- |
| `dev`     | 开发环境         | 无需确认                |
| `test`    | 测试环境         | 无需确认                |
| `staging` | 预发布环境       | 需二次确认 + 部署前备份 |
| `prod`    | 生产环境         | 需二次确认 + 部署前备份 |

1. ## 使用方式

1. ### 1交互式模式

不传任何参数即进入交互式引导：

```Bash
./generate-deploy-yaml.sh
```

交互流程：

1. **选择环境类型**：dev / test / staging / prod / 自定义
2. **输入服务器信息**：IP、端口、用户名、密码、部署路径、部署端口（默认 80）
3. **是否添加更多环境**：可连续添加多个
4. **选择默认环境**：多环境时选择默认使用哪个
5. **配置 Git 仓库**（可选）：
   1. 选择认证方式：**Token (PAT)**（推荐）/ HTTPS / SSH
   2. Token 方式只需输入 token，自动检测类型
   3. HTTPS 方式需输入用户名 + token
   4. SSH 方式需指定私钥路径
6. **选择输出位置**：`~/.claude/deploy.yaml` 或自定义路径
7. **预览确认**：显示配置表格（含 Git 信息），确认后生成

1. ### Token 认证（推荐，最简单）

使用 `github_pat_*` 或 `ghp_*` Token，三个字段即可：

```Bash
# GitHub Fine-grained PAT
./generate-deploy-yaml.sh \
  -e dev:192.168.1.100:22:root:mypassword \
  -g "https://github.com/user/repo.git|main|github_pat_xxxxxxxxxxxx"

# GitHub Classic PAT
./generate-deploy-yaml.sh \
  -e dev:192.168.1.100:22:root:mypassword \
  -g "https://github.com/user/repo.git|main|ghp_xxxxxxxxxxxx"
```

1. ### 命令行模式（单环境）

```Bash
./generate-deploy-yaml.sh -e dev:192.168.1.100:22:root:mypassword
```

1. ### 命令行模式（多环境）

```Bash
./generate-deploy-yaml.sh \
  -e dev:192.168.1.100:22:root:devpass \
  -e staging:192.168.1.200:2222:deploy:stgpass \
  -e prod:10.0.1.50:22:deploy:prodpass
```

1. ### HTTPS 认证（用户名 + Token）

```Bash
./generate-deploy-yaml.sh \
  -e dev:192.168.1.100:22:root:pass \
  -g "https://github.com/user/repo.git|main|https|myuser|ghp_xxxxxxxxxxxx"
```

1. ### SSH 认证

```Bash
./generate-deploy-yaml.sh \
  -e dev:192.168.1.100:22:root:pass \
  -g "git@github.com:user/repo.git|develop|ssh||~/.ssh/id_rsa"
```

1. ### 省略端口（默认 22）

```Bash
./generate-deploy-yaml.sh -e dev:192.168.1.100::root:mypassword
```

1. ### 指定输出路径

```Bash
./generate-deploy-yaml.sh -e dev:192.168.1.100:22:root:pass -o ./deploy.yaml
```

1. ## 生成文件结构

生成的 `deploy.yaml` 包含以下部分：

```YAML
default_env: dev

environments:
  dev:
    name: 开发环境
    host: 192.168.1.100
    port: 22
    user: root
    password: "xxx"
    deploy_path: /opt/app/dev
    requires_approval: false
    backup_before_deploy: false

git:
  repo_url: "https://github.com/user/repo.git"
  branch: main
  auth_method: token                # token / https / ssh
  access_token: "github_pat_xxx"
  clone_url: "https://x-access-token:github_pat_xxx@github.com/user/repo.git"

deploy:
  method: ssh
  build_cmd: ""
  artifact: ""
  health_check: ""
  rollback_keep: 3
```

> `clone_url` 字段自动生成，包含完整的认证信息，可直接用于 `git clone`。

### HTTPS 认证

```YAML
git:
  repo_url: "https://github.com/user/repo.git"
  branch: main
  auth_method: https
  username: "myuser"
  access_token: "ghp_xxx"
  clone_url: "https://myuser:ghp_xxx@github.com/user/repo.git"
```

### SSH 认证

```YAML
git:
  repo_url: "git@github.com:user/repo.git"
  branch: main
  auth_method: ssh
  ssh_key: "~/.ssh/id_rsa"
  clone_url: "git@github.com:user/repo.git"
```

1. ## 配合 generate-claude-md.sh 使用

### 完整配置流程

```Bash
# Step 1: 生成 CLAUDE.md（含部署指引段落）
./generate-claude-md.sh -r architect:opus,backend:opus -d -o ~/.claude/CLAUDE.md

# Step 2: 生成 deploy.yaml（填入实际服务器信息）
./generate-deploy-yaml.sh -e dev:192.168.1.100:22:root:mypassword

# Step 3: 在 Claude Code 中使用
# 对话中说："部署到 dev 环境"
```

### 两个脚本的关系

| 脚本                      | 生成文件      | 作用                                                |
| ------------------------- | ------------- | --------------------------------------------------- |
| `generate-claude-md.sh`   | `CLAUDE.md`   | 团队配置 + 部署指引（告诉 Claude 去读 deploy.yaml） |
| `generate-deploy-yaml.sh` | `deploy.yaml` | 实际的服务器连接信息 + Git 认证信息                 |

> `CLAUDE.md` 中的部署指引通过 `-d` 参数生成，它告诉 Claude："部署时去读 `~/.claude/deploy.yaml`"。

1. ## 安全提示

- `deploy.yaml` 包含服务器密码和 Git Access Token 等敏感信息
- 如果项目使用 Git，请将 `deploy.yaml` 加入 `.gitignore`
- 建议放在 `~/.claude/deploy.yaml`（全局位置，不在项目仓库内）
- 如需更高安全性，建议配置 SSH 免密登录替代密码存储
- Token 在交互模式预览时会脱敏显示（前缀 + 末尾 4 位 + 星号掩码）
- `github_pat_` 细粒度 Token 支持最小权限原则，建议仅授予仓库读取权限
