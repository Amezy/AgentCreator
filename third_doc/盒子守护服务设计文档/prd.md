# SuperTeam Wizard - AIBox 守护进程 PRD

## 1. 产品概述

### 1.1 产品背景

SuperTeam Wizard 是一款基于高性能大存储 AI Box（Mac Mini 形态）的软硬件结合产品。云端管理台可同时添加并管理 N 个 Box。每个 Box 上需要运行一个守护进程（`aibox-daemon`），负责与云端保持长连接，接收并执行云端下发的管理指令。

### 1.2 产品定位

`aibox-daemon` 是 Box 端的核心基础服务，作为云端与 Box 之间的通信桥梁，承载设备管理、用户管理、指令执行等核心能力。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| Box | AI Box 硬件设备，运行 Linux 系统 |
| Cloud | 云端管理台（SuperTeam Wizard 管理后台） |
| Daemon | Box 上的守护进程 `aibox-daemon` |
| 管理员用户 | Box 上拥有 root 权限的系统用户 |
| 设备序列号 | Box 的唯一硬件标识（设备 SN） |

## 2. 目标用户

| 角色 | 说明 |
|------|------|
| 云端管理员 | 通过云端管理台管理多个 Box 的运维人员 |
| Box 管理员 | Box 上创建的拥有 root 权限的系统用户 |

## 3. 功能需求

### 3.1 守护进程生命周期

#### 3.1.1 自启动

- **P0** Daemon 随系统开机自动启动（systemd 管理）
- **P0** 启动后自动读取本地配置，连接云端
- **P1** 支持通过 systemctl 进行 start/stop/restart/status 操作

#### 3.1.2 自恢复

- **P0** 进程异常退出后由 systemd 自动重启（间隔 5s）
- **P0** 连接断开后自动重连，采用指数退避策略（初始 1s，最大 60s）
- **P1** 本地持久化未完成的指令，重启后继续执行

### 3.2 设备注册与配对

#### 3.2.1 Box 主动注册

- **P0** Daemon 首次启动时，读取设备序列号（SN）
- **P0** 携带设备序列号向云端发起注册请求
- **P0** Box 根据设备序列号（SN）本地生成 `box_id`，注册时携带
- **P0** 云端审核通过后，设备进入已注册状态

#### 3.2.2 云端主动添加

- **P0** 云端管理员输入 Box 的序列号，主动添加设备
- **P0** Box 连接云端时，云端识别设备序列号，自动完成配对
- **P1** 支持云端生成激活二维码，Box 本地扫码激活

### 3.3 云端长连接

#### 3.3.1 连接管理

- **P0** 使用 WebSocket 协议建立与云端的持久连接
- **P0** 连接建立时携带设备序列号进行身份验证
- **P0** 心跳机制：Box 每 30s 发送 ping，云端回复 pong；超过 90s 无响应判定断连
- **P0** 断连后自动重连，指数退避（1s → 2s → 4s → ... → 60s）

#### 3.3.2 状态上报

- **P0** 连接建立后立即上报 Box 基础信息（OS、CPU、内存、磁盘、IP 等）
- **P1** 定时上报系统资源使用情况（每 60s）
- **P2** 异常事件主动上报（磁盘不足、服务异常等）

### 3.4 管理员用户管理

#### 3.4.1 创建管理员用户

- **P0** 云端下发创建用户指令，包含用户名和初始密码
- **P0** Daemon 在 Box 上创建 Linux 系统用户
- **P0** 将用户加入 sudo 组，授予 root 权限
- **P0** 设置初始密码
- **P0** 执行结果（成功/失败及原因）实时回报云端

#### 3.4.2 管理员用户管理

- **P1** 云端下发重置密码指令
- **P1** 云端下发删除用户指令
- **P1** 云端下发禁用/启用用户指令
- **P2** 查询 Box 上所有管理员用户列表

### 3.5 指令框架

#### 3.5.1 指令通用机制

- **P0** 每条指令有唯一 `cmd_id`，支持幂等执行
- **P0** 指令执行结果异步回报：成功、失败、超时
- **P0** 指令支持超时控制，默认 30s
- **P1** 指令执行日志本地持久化，支持云端查询

#### 3.5.2 指令类型（可扩展）

| 指令类型 | 优先级 | 说明 |
|----------|--------|------|
| `user.create` | P0 | 创建管理员用户 |
| `user.delete` | P1 | 删除用户 |
| `user.reset_password` | P1 | 重置用户密码 |
| `user.disable` | P1 | 禁用用户 |
| `user.enable` | P1 | 启用用户 |

## 4. 非功能需求

### 4.1 性能

- Daemon 常驻内存占用 < 50MB
- 心跳及状态上报对系统资源影响 < 1% CPU
- 指令响应时间 < 1s（不含指令执行耗时）

### 4.2 可靠性

- 断网恢复后自动重连，30s 内恢复连接
- 进程崩溃后 10s 内自动恢复
- 本地指令日志保留 30 天

### 4.3 安全性

- 指令执行前校验签名，防篡改
- 管理员用户密码不明文传输（使用 SHA-512 crypt 哈希）
- Daemon 以专用系统用户运行，仅在必要时提权

### 4.4 可维护性

- 支持日志分级输出（debug/info/warn/error）
- 日志自动轮转，单文件最大 100MB，保留 7 个文件
- 支持本地配置文件和环境变量配置

## 5. 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `cloud.ws_url` | `ws://api.superteam.com/ws/v1` | 云端 WebSocket 地址 |
| `cloud.api_url` | `http://api.superteam.com` | 云端 HTTP API 地址 |
| `heartbeat.interval` | `30` | 心跳间隔（秒） |
| `heartbeat.timeout` | `90` | 心跳超时（秒） |
| `reconnect.initial_delay` | `1` | 初始重连延迟（秒） |
| `reconnect.max_delay` | `60` | 最大重连延迟（秒） |
| `log.level` | `info` | 日志级别 |
| `log.dir` | `/var/log/aibox-daemon` | 日志目录 |
| `data.dir` | `/var/lib/aibox-daemon` | 数据存储目录 |

---

## 6. 部署要求

- 操作系统：Ubuntu 22.04+ / Debian 12+
- 运行方式：systemd service
- 安装路径：`/usr/local/bin/aibox-daemon`
- 配置路径：`/etc/aibox-daemon/config.yaml`
- 数据路径：`/var/lib/aibox-daemon/`
- 日志路径：`/var/log/aibox-daemon/`
